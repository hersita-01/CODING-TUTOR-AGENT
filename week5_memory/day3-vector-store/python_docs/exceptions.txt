# Exception Handling in Python
topic: exceptions
difficulty: beginner

## Introduction

Errors happen — bad input, unexpected data, or unforeseen conditions. Python's exception handling lets programs detect and respond to errors gracefully instead of crashing.

## Concept Overview

An exception disrupts normal program flow, often from things like division by zero or invalid conversions. Unhandled exceptions crash the program with a traceback. try holds risky code, except handles specific errors, and finally always runs, useful for cleanup like closing files.

## Syntax

try:
    statement
except ExceptionType:
    statement
finally:
    statement

## Explanation

When an exception occurs in try, Python jumps straight to the matching except block. Multiple except blocks can handle different error types. finally always executes, whether or not an error occurred, making it ideal for cleanup.

## Example 1

Code:

try:
    numerator = 10
    denominator = 0
    result = numerator / denominator
    print("Result:", result)
except ZeroDivisionError:
    print("Error: Cannot divide by zero.")
finally:
    print("Division operation attempted.")

Explanation:

Dividing by zero raises ZeroDivisionError, caught by except instead of crashing. finally always prints its message regardless of the error.

Output:

Error: Cannot divide by zero.
Division operation attempted.

## Example 2

Code:

def convert_to_integer(value):
    try:
        result = int(value)
        return result
    except ValueError:
        print(f"Error: '{value}' is not a valid number.")
        return None

print(convert_to_integer("123"))
print(convert_to_integer("abc"))

Explanation:

Valid strings convert successfully; invalid ones raise ValueError, caught to print a message and return None instead of crashing.

Output:

123
Error: 'abc' is not a valid number.
None

## Common Beginner Mistakes

Bare except blocks catch everything, hiding real bugs — catch specific exception types instead. Putting too much code in one try block makes it unclear what failed. Skipping try entirely means built-in exceptions can still crash the program.

## Debugging Tips

Read the full traceback carefully — it names the exact line and exception type. Temporarily catch Exception and print it during debugging to see the real error message.

## Best Practices

Catch specific exception types, not bare except. Keep try blocks small. Use finally for cleanup that must always run, and give clear error messages.

## Interview Questions

Question 1: What is the purpose of try and except.
Answer: To detect and handle errors gracefully without crashing the program.

Question 2: Difference between except and finally.
Answer: except runs only on a matching error; finally always runs.

Question 3: Why avoid bare except blocks.
Answer: They catch everything, hiding genuine bugs.

Question 4: What exception occurs dividing by zero.
Answer: ZeroDivisionError.

Question 5: What exception occurs converting an invalid string to int.
Answer: ValueError.

## Summary

try, except, and finally let Python handle errors gracefully. Catch specific exceptions and use finally for reliable cleanup.
